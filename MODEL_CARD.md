# Model card: prompting strategies and the extraction task

A model card for the prompt-strategy extractor that ships with this lab. Labs built from it
should copy this structure for every strategy and provider they gate on.

## Pipeline details

| Field | Value |
|---|---|
| Task | Structured extraction: a support message to a JSON record `{intent, product, severity}` with closed enums |
| Strategies | `zero_shot`, `few_shot`, `cot`, behind the `PromptStrategy` seam |
| Real model | `gemma3:27b` via Ollama, recorded once and replayed (`ReplayProvider`) |
| Stub | `StubProvider`, offline format path only (one fixed record), never a strategy claim |
| Injection defenses | delimiter fence, instruction-hierarchy system prompt, output-schema allowlist |
| Version | v1 (package 0.1.0) |
| Owner | Andrew Pyle |
| License | Apache-2.0 |
| Inputs | One support message |
| Outputs | One JSON record with three enum fields, or an unparseable or out-of-enum result |

## Determinism pins

| Pin | Value |
|---|---|
| Provider | `ollama` (recorded) |
| Model | `gemma3:27b` |
| Model digest | `a418f5838eaf7fe2cfe0a3046c8384b68ba43a4435542c942f9db00a5f342203` |
| Temperature | 0 |
| Seed | 7 |
| Ollama version | 0.32.1 |
| Cassette | `fixtures/cassettes/support_extract.json`, 120 entries |
| Recorded on | 2026-10-02 |

Temperature 0 and a fixed seed make a re-record reproduce the same responses. The cassette
key is `sha256(model, prompt)`, so a changed prompt is a hard miss, never a silent stale pass.

## Intended use

- Primary: a reference prompting lab that demonstrates a strategy comparison, a real token
  cost axis, an honest gate, and a prompt-injection defense with a deterministic allowlist.
- Users: engineers learning prompt evaluation, or building a lab from this family.
- Out of scope: answering real user messages, any decision affecting a person, any data other
  than the synthetic support set, and any claim that the stub understands text.

## Data

- Extraction set: `fixtures/support_extractions.jsonl`, 24 synthetic support messages.
- Injection set: `fixtures/injection_attacks.jsonl`, 12 synthetic indirect injections.
- Provenance and sha256 in [FIXTURES.md](FIXTURES.md). No real product, support, or personal
  data.

## Metrics and gate

| Metric | Why |
|---|---|
| field_accuracy | Share of field slots that match the gold record |
| record_exact | Share of examples with all three fields correct |
| schema_macro_f1 | Mean per-field macro-F1 across the schema |
| format_valid | Share of outputs that are parseable and in-enum |
| mean_completion_tokens | Vendor `eval_count`, the cost axis |
| asr (off and on) | Injection attack-success-rate, service output level |

Gate (in `eval_config.toml`): field_accuracy at least 0.55, format_valid at least 0.70, both
with a 0.05 tolerance band, plus the baseline margin, the saturation guard, the
between-strategy delta minimum, the provider-is-ollama check, and the injection precondition.

## Results (canonical run, primary strategy `few_shot`, n=24)

| Strategy | field_accuracy | format_valid | record_exact | schema_macro_f1 | mean completion tokens |
|---|---|---|---|---|---|
| zero_shot | 0.9028 | 1.0000 | 0.7500 | 0.9009 | 20.00 |
| few_shot | 0.9306 | 1.0000 | 0.7917 | 0.9311 | 19.00 |
| cot | 0.8750 | 1.0000 | 0.6667 | 0.8704 | 79.125 |

Baselines: majority field_accuracy 0.2917, empty 0.0000. Best strategy beats the best
baseline by 0.6389 (required 0.10). Between-strategy delta 0.1250 on record_exact. Not
saturated (top record_exact 0.7917). These numbers are generated by `make eval` and validated
against `docs/LEARNING.md` by `make check-learning-numbers`.

### Stub versus real

The stub is a format path. It returns one fixed record, so every strategy looks identical and
the gate fails it on purpose (byte-identical outputs and provider not `ollama`). The real
model is where the strategies separate.

| Signal | Stub | gemma3:27b (real) |
|---|---|---|
| Per-strategy outputs | identical | different per strategy |
| field_accuracy (best) | 0.2778 | 0.9306 |
| format_valid | 1.0000 | 1.0000 |
| Token counts | whitespace estimate | vendor `eval_count` |
| Gate outcome | FAIL (vacuous guard) | PASS |

## Injection result

The injection sub-experiment is INSUFFICIENT. With all defenses off, `gemma3:27b` obeyed 0 of
12 attacks, so the defenses-off attack-success-rate was 0.0 and the lab cannot prove the
defenses reduced it. This is reported honestly rather than claimed as a win. The output-schema
allowlist still gives a deterministic guarantee: the sentinel is not an enum value, so it can
never reach a field when defenses are on (verified in the tests).

## Limitations

- record_exact is below 1.0 because the harder messages need reasoning the model does not
  always get right. This is expected and keeps the task from saturating.
- Chain-of-thought scored lower than zero-shot here and cost about four times the output
  tokens. That is a result for this short extraction task, not a general verdict on CoT.
- The injection result is one model on 12 synthetic attacks. It shows the harness and the
  deterministic allowlist, not a general robustness claim.
- A 24-example set exercises the gate. It is not large enough to call close strategies apart,
  which is why the headline delta's confidence interval overlaps zero.

## Ethical considerations

- The data is synthetic and holds no personal information, so no consent issue arises.
- A real extraction service feeds downstream automation. A wrong severity could misroute an
  urgent ticket, so the lab reports per-field accuracy rather than one number.
- The sentinel `ADMIN` is a harmless marker for obedience. The defenses here are a
  demonstration, not a complete injection defense for production.

## Caveats and recommendations

Treat few-shot as the floor to beat and the baselines as the floor it must clear. Before
trusting an extractor in production, grow the dataset, add a real faithfulness or severity
judge, and measure injection on a model that can actually be fooled.
